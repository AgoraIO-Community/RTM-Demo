### 目标与边界

把 Ink 的颜色、控件尺寸、动效和焦点规则对齐 Agent UI 的 Agora Website foundation 与 Basic 控件，让 RTM 体验馆和 Agent UI 系产品属于同一视觉家族。

不变的部分：三栏结构与响应式断点、业务流程和文案、等宽字体承担机器可读信息的规则、数据流的版式与 API／EVENT 类型色、72px 方格、根字号随视口缩放、`--ink-*` 作为唯一 token 前缀、单一 `styles.css`。不引入 Agent UI 源码、Radix 或新的 CSS 文件；只按 Agent UI 规范改写 token 值和组件规则。

### 字体

- UI 字体改为 `"MiSans", -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", sans-serif`。保留中文系统字体作回退，MiSans 未加载时不跳到西文字体。

- 等宽栈不变，继续承担编号、时间、耗时、API 名、状态词、计数与 TAG。
- 正文与按钮字重从 500 改为 **400**，标题与强调用 600。字重只用 400／600，取消 500 与 700。v1.2 用 500 是为了清晰度，改为 400 后需在 Windows 与低 DPI 屏复查。

### 控件尺寸与按钮

| 项目 | v1.2 | v2.0 |
| --- | --- | --- |
| 主区按钮（创建、加入、拨号、发送） | 38px | `md` 40px |
| 顶栏、侧栏、筛选胶囊、数据流工具 | 自定义 | `sm compact` 32px |
| 手机或粗指针命中区 | 不统一 | ≥ 46px，可见尺寸可更小 |
| 消息输入框 | 46px | 46px（与触屏目标一致） |
| 控件圆角 | 6px | 6px（不变） |
| 按钮标签／图标 | 13px / 不统一 | 13px regular / 16px |

按钮分三种优先级，一个操作区只放一个 primary：

| 变体 | 静止 | 悬浮 | 本项目用法 |
| --- | --- | --- | --- |
| primary | foreground 底、background 字 | 底色转 signal | 创建房间、加入、呼叫、接听、发送 |
| secondary | raised 底、foreground 字 | hover 底 | 完成、取消呼叫、复制、邀请上麦 |
| quiet | 透明、muted 字 | hover 底 | 折叠、清空、关闭、次级文字操作 |

危险操作（踢出、封禁、挂断、拒绝）沿用 secondary 外形，文字与图标用 danger；需要二次确认的操作采用 InlineConfirm 的原位确认规则。

请求进行中使用 busy：保留按钮宽度与可访问名称，居中显示 spinner，阻止重复触发。悬浮与按压不改变控件的位置和尺寸，按压只加内凹阴影。

全局 `:focus-visible` 改为 `2px solid var(--ink-focus)`，`outline-offset: 3px`。取消现有按组件分别定义的焦点颜色；文字链接保留底色提升作为补充。

### 动效

| token | 值 | 用途 |
| --- | --- | --- |
| `--ink-duration-fast` | 200ms | 按钮、图标按钮与输入框的悬浮色变 |
| `--ink-duration-standard` | 360ms | 数据流新条目入场（原 .35s） |
| `--ink-duration-slow` | 600ms | 预留给侧栏展开与遮罩，当前未使用 |
| `--ink-duration-press` | 140ms | 按压反馈 |
| `--ink-ease-standard` | `cubic-bezier(.22,.61,.36,1)` | 悬浮色变、边框与头像呼吸（原 `ease-in-out`） |
| `--ink-ease-enter` | `cubic-bezier(.16,1,.3,1)` | 数据流入场（原 `ease-out`） |
| `--ink-ease-exit` | `cubic-bezier(.4,0,1,1)` | 预留，当前未使用 |

数据流边框呼吸（1.8s × 2）和说话头像呼吸（1.8s 无限）属于 RTM 业务语义，保留时长，只把缓动改为 standard。滚动条显隐保持 v1.2 的 0.3s／0.08s，不并入 token。文字与浮层出现只做淡入，不位移、不模糊。减少动态效果时移除全部过渡。

### 间距

采用 4px 节奏。偏离网格的值调整为最近的网格值：rowP 11 → 12，公屏消息间距 11 → 12（容器高度相应改为 `calc(1.5em * 5 + 12px * 4)`），btnH 38 → 40，traceP 14 → 12。pad 24、gap 12 不变。左栏体验流程的分区间距（任务区与资源区之间、Console 与开发文档之间）由 24 改为 20，抵消行距增加，保证 16:9 高窗口下任务列表不出现滚动。

### 品牌渐变

保留声网品牌渐变 `#f6a34a → #ee5a9a → #8b5cf6 → #38bdf8`，用途不变：只用于左栏进度条与 Console CTA 描边。这是本项目在 Agent UI 家族里的品牌标识，属于「材质边界」允许的本地差异。其余交互信号（链接、焦点、primary 悬浮）一律用 signal，不使用渐变。

### MiSans 字体

MiSans 为小米免费商用字体，[许可协议](https://hyperos.mi.com/font/zh/download/)禁止对字体改编、二次开发，也禁止单独分发字体文件。因此：

- 只使用官方 `MiSans.zip` 中原样的 `MiSans-Regular.woff2`（400）与 `MiSans-Demibold.woff2`（600），不做子集化或格式转换。
- 两个文件放在 `src/app/assets/fonts/`，该目录已列入 `.gitignore`，不随仓库发布；本地开发与部署时从官网下载后放入。
- `styles.css` 用 `@font-face` 声明，`font-display: swap`；`--ink-font-ui` 以 `"MiSans"` 开头，后接系统栈。文件缺失时构建仍通过，页面回退系统字体。
- 原型通过 `../../src/app/assets/fonts/` 相对路径引用同一份文件。
- 两个字重各约 4.9MB，首次加载先以系统字体显示，字体就绪后替换。
- 协议要求在软件中注明使用了 MiSans；项目负责人决定暂不在界面中添加该声明。

## 全局框架

设计基准为 1440 × 900。大窗口按可用宽高协调放大字号、控件、图标、侧栏和间距，保持三栏比例，不设置固定的放大上限；较矮窗口按可用高度限制放大倍率，手机沿用紧凑布局。下文尺寸均为基准值：顶部 56px，左右栏展开宽度 252px／420px，折叠后各 48px；中区 `padding:24px`，canvas 底上叠加 72px 方格，侧栏与房间使用 surface。

顶栏保留品牌、七个一级场景、页面级 RTM 连接状态和主题按钮。场景为语聊房、1V1呼叫邀请、电商直播、在线课堂、虚拟世界、游戏互动、文档协同；语聊房与 1V1 呼叫邀请已实现。主题按钮在 light／dark 间立即切换，生产偏好由 `theme.ts` 保存，无主题过渡动画。

RTM 左侧展示声网 Logo，点击打开[声网官网](https://www.shengwang.cn/)；左栏底部提供[了解产品详情](https://www.shengwang.cn/realtimemessage/?utm_source=rtedemo&utm_medium=menu)。两个入口均在新标签页打开，Logo 在浅深主题下保留品牌色。

左栏内容充足时按自然高度排列，Console 和开发文档紧跟任务列表；空间不足时任务列表独立滚动，标题和任务进度保持可见。视口高度不超过 576px 时，为任务区保留至少 96px，Console 与开发文档在独立资源区内滚动，全部入口均可通过鼠标或键盘到达。“了解产品详情”始终位于底部，较矮窗口和手机抽屉中也直接可见。

内部滚动条统一为透明轨道、细圆角滑块，默认隐藏。鼠标移入、焦点进入或滚动时短暂显示，停止操作后淡出；鼠标或焦点停留不会持续显示，拖动期间保持可见。适配浅深主题，显隐不挤动内容；顶部场景导航保持隐藏滚动条，允许横向滚动。

第 03–07 项导航不跳转，使用禁用样式，悬浮、聚焦或触屏点击时，在对应导航项下方显示紧凑提示“即将上线，敬请期待”，不使用页面中央通知。保留旧 URL 的占位页兼容。

生产场景导航使用整页跳转，页面只运行当前场景的一个 RTM Client，不缓存跨场景 Session。切换后主题偏好保留，体验进度、数据流和侧栏折叠态从新页面重新开始；历史返回恢复缓存页面时重新加载。设计原型仅模拟视图切换来预览布局，不承载 RTM 生命周期。

左右栏标题分别使用路线与脉冲图标（16 × 16、stroke 1.8），标题后保留原控制项。侧栏顶部使用自身 padding，不额外增加与房间标题强制对齐的横线。三栏不提供拖拽分隔器。

小于 1280px 时右栏优先收起，小于 1024px 时左栏也收起。760px 及以下，两侧保留 48px 窄栏，展开后覆盖主区并有可关闭遮罩；主区 padding 12px，房间改成单列。页面和中间主框架不滚动，内容溢出由内部组件处理；桌面房间标题和输入栏保持可见，手机房间在卡片内滚动，底部操作始终可达。

## 左侧体验流程

标题为“建议体验流程”，分为场景任务、Console 创建项目入口和开发文档。开发文档依次提供产品简介、最佳实践、API参考和当前语聊房 Demo 源码，源码链接直接打开仓库内 `src/scenes/voice-room/README.md`。场景任务只有“已完成／待体验”两种显示状态；操作说明在悬浮、键盘聚焦或触屏点击时查看，不展开第二层子任务列表。

五个任务依次为“建立房间连接”“看见成员在线”“申请与审批上麦”“发送房内消息”“同步房间状态”。进度条使用品牌渐变；完成状态用 success，未完成用中性色。Console CTA 仅用渐变描边，不用渐变实心底。

1V1 呼叫邀请为四个任务：“发起或接收呼叫”“响应呼叫邀请”“建立真实音频”“结束通话”。首项在主叫成功发送邀请，或被叫消费有效邀请时完成；发送失败和被忽略的邀请不推进任务。主叫发送成功后显示“对方正在响铃”，被叫显示来电，不额外发布振铃回执。“响应呼叫邀请”只由有效的接听或拒绝响应推进，取消、挂断和自动忙线不计入。“结束通话”在呼叫结束并完成清理、回到空闲后完成，不要求切换麦克风。RTM 登录由页面自动完成，不作为体验任务，也不计入任务完成数。

生产进度依据成功 API 和已消费的业务状态推进，失败调用、默认麦位、本地聊天回显不能冒充远端证据。原型中的任务状态仅用于演示视觉。

## 创建与加入入口

新标签页文字链接统一使用语义色 `--ink-link`（浅色 `#075c9a`、深色 `#00c2ff`，与 signal 同色），加 8% 淡底色、细下划线与 4px 圆角；悬浮或键盘聚焦时底色升至 14%，保留轻量入口层级。

入口包含眉标、标题、简短说明和创建／加入两张卡片；加入卡片的名称说明处提供“同机体验？新开听众页 ↗”轻量文字链接。当前页创建房间后，新标签页可输入同名房间加入，不要求使用另一台设备。新标签页使用干净场景 URL 与 `noopener noreferrer`，不复制当前身份参数。桌面两张卡片的名称说明区预留两行高度，保持昵称字段与提交按钮对齐。每张卡片独立包含房间名称、选填昵称及提交按钮；不增加邀请复制、粘贴链接或登录资料表单。

- 字段标签为“你的昵称（选填）”。空值沿用角色默认：房主 `Host`，听众为基于 UID 稳定生成的英文名加三位数字。
- 昵称先校验非法字符，再做 NFC 规范化和首尾空白清理；最多 20 个 Unicode 码点，不能使用 HTML `maxlength=20` 代替码点计数。允许中文、数字、Emoji、组合 Emoji 及重名。
- 拒绝换行、不可见控制字符、孤立代理项和没有可见内容的非空输入；保留组成正常文字／Emoji 所需的合法连接符。无效输入保留草稿、显示字段错误并禁用对应提交。
- 中文输入法组合输入的 Enter 不提交。非法换行粘贴必须提示错误，不能被单行输入框悄悄删掉。
- 两张卡片分别保存草稿；失败、取消或暂离后可修改。进入房间后本轮昵称固定，不增加房内改名入口。
- Host 暂时离开后，创建卡片显示“以 Host 身份返回”，恢复相同 roomId、UID 与 nickname；解散后不显示该入口。
- UID 自动生成且与昵称分离。重名不会合并用户，麦位、权限协作、邀请与封禁仍按 UID 区分。生产 URL 刷新保留 UID 与昵称；原型不模拟持久身份或链接恢复协议。
- 头像取首个完整字素，优先使用 `Intl.Segmenter`，兼容降级至少保留完整 Unicode 码点。

精确校验与默认值以 [nickname.ts](../../src/scenes/voice-room/nickname.ts) 和 [audience-display-name.ts](../../src/scenes/voice-room/audience-display-name.ts) 为准。

## 1V1 呼叫结束与空闲

空闲态版式见「场景入口页（语聊房与 1V1 统一）」。`CALL · PEER` 卡片在对方呼叫 ID 提示下方提供“同机体验？新开体验页 ↗”轻量文字链接，使用干净场景 URL 与 `noopener noreferrer`，新页面生成独立呼叫 ID。发出呼叫、来电、接通中与通话中在右卡内居中显示头像、状态眉标、对方名称、说明、倒计时与操作。真实音频联调请戴耳机。

1V1 呼叫状态标签直接使用业务主状态的大写下划线名称：`IDLE`、`OUTGOING_SENDING`、`OUTGOING_RINGING`、`INCOMING_RINGING`、`ACCEPTING`、`MEDIA_CONNECTING`、`ACTIVE`。每次邀请独立实例，结束直接回到 `IDLE` 并显示结束原因，后台清理不阻塞新邀请，不展示 `ENDING`。主叫与被叫各自更新本地状态，完整图见[场景状态流转与时序文档](../../src/scenes/one-to-one-call/docs/1v1呼叫邀请状态流转与时序.md)。

发送邀请期间只显示“正在发送邀请…”，不显示接听倒计时；INVITE publish resolve 后进入响铃态，从 30s 开始。被叫收到来电后从自己的 30s 开始；接听与重发不重置窗口。首帧使用当前时间计算，不能把页面空闲的时间叠加到倒计时中。

邀请发送失败返回后立即停止当前呼叫，不自动重试：根据最新本地连接状态，CONNECTED 显示“对方不在线”，其他状态显示“本地网络异常，呼叫失败”。断线蒙层同步显示本地网络错误，避免遮住失败反馈；恢复连接后可重新发起。原始 SDK 错误保留在数据流。发送成功但无人接听才等待邀请截止；最后一刻接听仍须在截止前完成信令握手。

邀请到期时主叫显示“对方无应答”，被叫显示“邀请已过期”。被叫正在等 ACK 时同样会在原截止时间自行结束并回到空闲；再次呼叫生成新的 callId。

拒绝、取消、忙线、邀请过期、对方离线、无响应、媒体失败、媒体超时及正常结束均在 RTC 清理完成后自动回到 `IDLE`。结束原因显示在 `CALL ENDED` 卡片标签下方，并显示“可以发起或接听新的呼叫。”；拨号表单和昵称编辑恢复可用。新呼叫自动替换旧结果，“完成”作为次要按钮，仅收起提示，不影响接听或拨号能力。

## 房间、麦位与公屏

房间卡片圆角 8px、1px line 边框，背景 surface，使用下表的双层投影。桌面两列为 `minmax(0,1fr) / 300px`，标题高 76px，底部输入条。左列依次为麦位、公告、公屏；右列房主显示治理面板，听众显示邀请卡、我的状态与在线听众。听众同样保留右侧面板。

八个麦位保持四列，桌面高 132px、手机高 104px。普通麦位为 1px line、圆角 10px；空麦位为虚线。头像 44px，名称使用 UI 字体，机器状态词使用等宽字体。只有当前选中麦位显示卡片 ring，Host 不因身份自动选中；说话状态只让头像进行 1.8s 无限呼吸，不改变卡片边框。

房主麦位在卡片上缘放置 **22 × 22px 实心皇冠**，定位 `top:-12px; left:8px`，容器横向 padding 2px、圆角 3px、surface 背景。它不能遮挡头像或麦克风图标；没有“房主”可见文字，仍保留 `aria-label` 和 `title`。房间标题的角色徽标不受此调整影响。

公告保留分节标题与普通正文，不增加独立底色卡片。公屏姓名和正文同行，系统消息保留中性色；不恢复历史原型的独立时间戳列。

公屏字号 13px、行高 1.5、消息间距 12px，容器最大高度 `calc(1.5em * 5 + 12px * 4)`，即 145.5px。每条消息不收缩，最小高度一行；超过后上下滚动，全部历史仍在列表中。长消息按原规则换行，所以可能少于五条完整消息同时可见，不能截掉消息凑五条。新消息到达仍滚到底部；消息区支持键盘聚焦滚动。

Host 治理面板的在线听众每行提供邀请上麦、踢出与封禁，不要求先选中对应麦位。Host Presence 暂时缺失时，Audience 的房主麦位仍显示 `Host` 和 `AWAY`，不暴露房主 UID。

消息栏保持单行排列，文字输入框高度为 46px；窄屏空间不足时沿用响应式换行。输入条保留文字发送、Emoji、礼物、爱心与麦克风／上麦操作。生产发送成功只清空本次提交对应的草稿，等待期间的新输入与失败草稿保留。

## RTM 数据流

展开标题只包含脉冲图标、“RTM 数据流”与清空／连接过滤／折叠控件，**不显示 API／EVENT 分类汇总**。下面的两个筛选胶囊仍显示类型色点、标签与计数；折叠窄栏保留总数。

数据流按时间倒序显示，**最新记录在顶部**；相同时间戳按采集序号倒序排列。类型筛选、连接过滤后仍保持该顺序。新记录进入、筛选变化和重新展开侧栏时，列表定位顶部。此变动仅作用于展示副本，采集与归并顺序保持不变；公屏仍按原顺序显示，新消息到达滚到底部。

列表每行最小 70px、圆角 6px，行间距 10px，内边距 `14px 12px`；左列时间宽 86px，右列 `minmax(0,1fr)`，列间距 10px。第一行包括 API／EVENT 类型标签、名称、publish 的 USER／MESSAGE tag 和可用耗时；第二行完整展示摘要并自动换行，条目随内容增高。只有首行过长的 API 名保持省略。

所有条目背景使用 surface，外框 1px line，左框 3px 类型色。API 使用薄荷绿，EVENT 使用天蓝；类型色也用于标签和筛选圆点，不能将整行恢复为历史 wash 配色。

第二行直接完整展示摘要和错误详情，原生 `title` 仍保留用于快速查看全文；失败状态用 danger 内描边表达。设计系统额外提供可聚焦的摘要示例，属于设计稿阅读辅助，不表示生产新增了浮层组件。

新到条目使用入场 `0.36s ease-enter`，随后边框呼吸 `1.8s ease-standard .3s 2`，结束后恢复静态；呼吸只改变边框、光晕，surface 行底始终不变。减少动态效果设置下关闭这些动画。公屏与数据流各自滚动，清空数据流不改变房间或体验进度。

## 字体、边框与资源

UI 字体为 MiSans 加系统栈回退：`"MiSans", -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Helvetica, sans-serif`。正文基准字重为 400，并沿用系统默认字形渲染，不设置 `-webkit-font-smoothing: antialiased`。等宽栈为 `ui-monospace, "SF Mono", Menlo, Consolas, monospace`，用于编号、时间、耗时、API 名、机器状态词、计数与 TAG。字重只使用 400／600，与 MiSans 的 Regular／Demibold 对应（见「MiSans 字体」）。

常规结构边框 1px；数据流类型左框 3px，选中 ring 和失败描边按组件定义。虚线表达空麦位；语聊房与 1V1 呼叫工作台的 stage shadow 是明确允许的层级（深色为 none）。圆角以生产组件为准：工作台 8px、麦位 10px、常规控件与数据流 6px、角色与类型标签 3px、胶囊全圆、头像 50%。

品牌渐变为 `#f6a34a → #ee5a9a → #8b5cf6 → #38bdf8`，仅用于进度条和 Console CTA 描边。成功、危险与 API／EVENT 使用独立语义色。

## 状态与工程边界

原型支持本地昵称输入与进入视图、聊天追加、主题切换、侧栏和数据流筛选；新模拟 trace 出现在顶部。麦位治理、申请审批与公告等展示固定示例，部分按钮仅追加模拟 trace，不实现完整业务闭环。模拟时间和耗时不代表 SDK 实测结果，原型动作不作为产品功能验收。

生产应用每个 Tab 一个角色和一个 RTM client；Storage 是房间权威状态，nickname 来自 Presence，消息通过 UID 关联显示名称。操作是否成功及退出清理由真实 API 结果和事件决定，不能统一改成“先乐观更新再校正”。Demo 的治理仍为客户端协作，不代表服务端强制权限。

业务与协议细节继续以根 [AGENTS.md](../../AGENTS.md) 和 [语聊房说明](../../src/scenes/voice-room/README.md) 为准。本交接仅规定已确认的展示与交互，不改变真实房间生命周期。
