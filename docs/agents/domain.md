# 领域文档约定

本约定与具体 Agent 工具无关。按照根 [AGENTS.md](../../AGENTS.md) 工作时，使用同一套术语和架构决策，不依赖 Claude 或特定技能命令。

## 读取顺序与布局

- 先读根 [CONTEXT.md](../../CONTEXT.md)，沿用项目术语。
- 如果存在 `docs/adr/`，再读与本次修改相关的架构决策记录。
- 修改具体场景时，继续阅读场景 README 和正式 `docs/`；历史实施票不覆盖现行协议或视觉规范。

本仓库只有一个应用，采用单上下文布局：根 `CONTEXT.md` 加 `docs/adr/`。ADR 使用 `NNNN-<slug>.md`，从 `0001` 递增。文件或目录尚不存在时不必预先创建；只有确认需要落定新术语或架构决策时才补充。

## 术语与冲突

issue、文档、重构提案和测试描述中的领域概念使用 `CONTEXT.md` 已定义的写法。例如区分“暂时离开”与“解散”、邀请实例与媒体会话，不为了措辞变化引入新的同义概念。

术语表未收录的概念先沿用当前代码和正式文档的叫法；确需新增时同步补充定义。不要把历史票中的旧导航、同页多实例或旧目录方案当作当前领域模型。

发现新需求与现行文档或 ADR 冲突时，明确指出冲突和影响，请用户确认后更新决策，不默默覆盖，也不把已废弃方案并列为现行选项。
