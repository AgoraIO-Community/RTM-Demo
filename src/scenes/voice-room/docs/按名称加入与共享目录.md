# 按名称加入与共享目录

> **严禁在生产环境参考本 Demo 的 Metadata 目录实现。** 生产环境必须由客户 App Server 负责房间创建、名称查询、成员准入、封禁和生命周期，并在服务端完成鉴权与并发控制。本 Demo 没有服务端，仅为了演示“输入同一房间名称即可加入”的交互，临时使用 RTM Channel Metadata 模拟共享目录。它不是安全边界，也不提供生产级一致性保证。

## 两类频道

每个名称对应一个稳定的 Metadata-only 目录频道：

```text
vrn-v1-<Base64URL(SHA-256("voice-room:v1:" + canonicalName))>
```

例如“周五语聊”经过 Unicode NFC、首尾空白清理和内部空白折叠后得到 `canonicalName`，再确定性生成 `nameKey`。所有输入同一规范名称的客户端都会读取同一个目录频道。

实际房间频道与名称无关，由 Host 每次创建时随机生成：

```text
voice-room-<UUID>
```

同名房间解散后重新创建会得到新的 `roomId`，旧 URL 不能跳转到新房间。

## 目录 DTO

目录频道只使用一个 Metadata key：`entry`。其 JSON 值为：

```ts
interface NameDirectoryEntry {
  schemaVersion: 1;
  canonicalName: string;
  roomName: string;
  roomId: string;
  hostUserId: string;
  status: "active" | "inactive";
  createdAt: number;
  endedAt?: number;
  banUserIds: string[];
}
```

实际房间 Metadata 仍只有四个 key：`hostUserId`、`announcement`、`seats`、`forcedMutedUserIds`。目录与实际房间是两个不同频道，每个页面仍只创建一个 RTM client。

## Host 创建时序

```text
规范化名称并计算 nameKey
→ getChannelMetadata(nameKey)
→ 若 active 记录属于当前 Host，则恢复原 roomId；属于其他 Host 则提示名称被占用
→ 生成随机 roomId
→ 使用读取到的 majorRevision 写入 entry=active
→ presence.setState(roomId, nickname)
→ subscribe(roomId)
→ subscribe 成功立即开放房间交互并启动 RTC
```

目录写失败时，Host 间隔 300ms 重新读取并最多再试两次。读取到当前 hostUserId 与本轮 roomId 表示未知写入结果实际已经成功；读取到其他 Host 的 active 记录或三次仍无法确认时，提示“房间被占用，请更换房间名再次创建”。目录登记成功但实际房间 subscribe 失败时，只在 hostUserId、roomId 仍属于本次创建且 majorRevision 匹配时删除记录。

## Audience 准入时序

```text
规范化名称并计算 nameKey
→ getChannelMetadata(nameKey)
→ 校验 entry 存在、status=active、roomId 与 URL 一致且本 UID 未被封禁
→ presence.setState(roomId, nickname)
→ subscribe(roomId)
→ subscribe 成功立即开放房间交互并启动 RTC
```

准入判断必须发生在订阅实际房间之前。这里调用 `getChannelMetadata()` 只是无服务端 Demo 的替代实现；生产环境应改为请求 App Server。

Host 和 Audience 都不订阅目录。`subscribeRoom()` 的 Promise 只表示 SDK `subscribe()` 完成，不代表 Presence 或 Storage 首快照已到达；权威状态尚未到达时，依赖房间 Metadata 的操作保持禁用。

## 断线与生命周期

Audience 断线时显示蒙层。SDK linkState 恢复 CONNECTED 不能撤销蒙层，必须等待实际房间 Storage 事件：四项 Metadata 完整时恢复交互；Metadata 为空时认为房间已解散，离开 RTC、退订实际房间并完成本地清理。重连不重复 subscribe，也不读取目录或实际房间 Metadata。

Host Presence 缩减只表示房主暂时离开，不解散 active 房间。Host 刷新、关闭标签页、浏览器崩溃或断网都不修改目录。

Host 主动解散依次把目录写为 inactive、广播 room.dissolved、清理实际房间四项 Metadata、退订实际房间并删除目录记录。实际房间清理失败时间隔 300ms 最多尝试三次；实际房间或目录仍未清理时保留“重试清理”操作，重试只补做未完成部分。删除目录前重新读取并核对 hostUserId 与 roomId，删除操作携带 majorRevision，避免迟到清理删除同名新房间记录。Audience 收到 room.dissolved 或空 Metadata 都按相同退出语义处理。

## 封禁通知

Host 封禁成员时并行写目录 `banUserIds`、清理麦位并发送 `member.ban` USER P2P；三个动作互不阻塞。踢出并行清理麦位与发送 `member.kick`。

P2P 超时、目标离线或发送失败不会回滚已完成的目录或麦位操作，Host 页面显示失败提示，并按目标 UID 保存待处理动作；检测到该 UID REMOTE_JOIN 时自动重发，成功后删除，失败则继续保留。这些能力仍是客户端协作，不构成服务端强制权限。

## URL

页面 URL 使用一个 `data` 参数：

```ts
{
  version: 2;
  nameKey: string;
  roomId: string;
  role: "host" | "audience";
  pageUid: string | null;
  nickname: string | null;
}
```
