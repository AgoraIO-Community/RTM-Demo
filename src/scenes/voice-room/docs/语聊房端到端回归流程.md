# 语聊房端到端回归流程

更新日期：2026-09-16

本文把 Host 与 Audience 两个页面的人工组合操作固化为可重复执行的回归矩阵。每条流程同时检查用户可见状态和 RTM 数据流，不以“按钮可点击”代替业务结果。

## 自动化边界

- 场景导航使用整页跳转，各页面只运行当前场景。外壳单测覆盖 Strict Mode 只创建／登录一次、pagehide 与真正卸载幂等注销；导航 E2E 覆盖文档重新加载、返回场景与浏览器历史返回、主题保留、面板状态重置。页面重新加载后体验进度和数据流从本次访问开始，不复用旧 Session。

- Playwright 在同一个 BrowserContext 中打开两个真实页面，一个页面运行 Host，另一个页面运行 Audience；每个页面仍只有一个角色和一个 `AppRtmSession`。
- 测试使用占位 App ID，并只在 Vite `e2e` mode 启用同源 RTM adapter。目录与房间 Metadata、Presence 通过 `localStorage` 共享，Message、Presence 和 Storage 事件通过 `BroadcastChannel` 投递。
- adapter 复现本场景依赖的 RTM 可观察契约：订阅首快照、远端加入/离开/状态变化、完整 Metadata 事件、房间消息和 USER P2P。生产构建仍创建真实 Agora RTM client。
- 目录 API/Event 按产品约定不进入数据流。下表只写实际房间的 RTM API/Event。
- 自动化不验证 Agora 服务可用性、真实网络重连、Token、消息服务端送达、RTC 音频采集与播放。这些仍需使用有效凭证、两个真实 Tab 和耳机人工验收。
- 双端业务闭环只在 `desktop-chromium` 执行一次；`mobile-chromium` 继续由既有响应式布局用例覆盖。

运行全部 E2E：

```bash
npm run test:e2e -- e2e/lab.spec.ts
```

只运行本文流程：

```bash
npx playwright test --project=desktop-chromium e2e/lab.spec.ts \
  -g "Host 创建后 Audience 可按同名加入、退出并再次加入|语聊房双端业务回归"
```

## 流程矩阵

表中的 `voice-room-...-xxxx` 表示数据流使用的频道短标识，`xxxx` 是本轮随机 `roomId` 的末四位。

| 编号 | 前置状态 | Host 操作 | Audience 操作 | Host 预期 UI 与数据流 | Audience 预期 UI 与数据流 | Playwright 用例名 |
| --- | --- | --- | --- | --- | --- | --- |
| VR-E2E-01 | 两个页面均在语聊房入口；Host 昵称“小周”，Audience 昵称“小明” | 输入唯一房名并创建；等待 Audience 加入 | 输入同名加入；退出；使用同名再次加入 | 在线听众出现“小明”；退出后消失，再加入后恢复。首次加入出现 `presence REMOTE_JOIN 小明 (uid缩写)`，退出出现 `REMOTE_LEAVE`，重入再次出现 `REMOTE_JOIN` | 成功进入而非“未找到房间”；首轮收到 Presence/Storage `SNAPSHOT`；退出有 `rtm.unsubscribe voice-room-...-xxxx`；重入再次出现 `presence.setState`、`rtm.subscribe voice-room-...-xxxx` 和首快照 | `Host 创建后 Audience 可按同名加入、退出并再次加入` |
| VR-E2E-02 | 双方已入同一房间并互相在线 | 发布公告“今晚八点开始”；发送爱心 | 发送聊天“大家好” | 公告更新；公屏出现“小明 大家好”。API 有 `storage.setChannelMetadata voice-room-...-xxxx: announcement=今晚八点开始`；Event 有 `message chat.message from 小明: 大家好`；爱心 API 首行为 `rtm.publish MESSAGE`，第二行为 `voice-room-...-xxxx: to ALL emoji.reaction` | 公告更新；公屏出现“小周 送出爱心”。Storage `UPDATE` 展示包含新公告的四项全量 Metadata；聊天 API 首行为 `rtm.publish MESSAGE`，第二行为 `voice-room-...-xxxx: to ALL chat.message`；收到 `emoji.reaction from 小周` | `公告、聊天与爱心同步到双方，并留下对应 API/Event 数据流` |
| VR-E2E-03 | 双方在线，2 号麦为空 | 在排麦申请中拒绝小明 | 点击 2 号空麦发起申请 | 排麦队列出现“小明 → SEAT 02”；Event 为 `USER seat.request 2号麦 from 小明`；拒绝 API 首行为 `rtm.publish USER`，第二行为 `to 小明 seat.rejected 2号麦` | 底部进入“等待审批”，拒绝后 toast“上麦申请被拒绝”并恢复“申请上麦”；申请 API 首行为 `rtm.publish USER`，第二行为 `to 小周 seat.request 2号麦`；收到 `USER seat.rejected 2号麦 from 小周` | `Audience 申请 2 号麦后 Host 拒绝，双方收到 USER 信令数据流` |
| VR-E2E-04 | 双方在线，2 号麦为空 | 同意小明的排麦申请 | 点击 2 号空麦申请；获批后主动下麦 | 同意后 2 号麦显示“小明”，下麦后恢复空麦；同意和下麦消费后分别出现 `storage.setChannelMetadata ...: seats=2号麦 小明` 与 `...: seats=2号麦 空`；收到 `seat.left 2号麦 from 小明` | Storage 全量事件驱动 2 号麦显示自己；主动下麦 API 首行为 `rtm.publish USER`，第二行为 `to 小周 seat.left 2号麦`，随后执行 `presence.removeState voice-room-...-xxxx: muted, microphoneError`，恢复“申请上麦” | `Audience 申请获批后占用 2 号麦，并可主动下麦` |
| VR-E2E-05 | 双方在线，2 号麦为空 | 选择 2 号麦，邀请小明上麦 | 在右侧邀请卡中拒绝 | 邀请 API 首行为 `rtm.publish USER`，第二行为 `to 小明 seat.invited 2号麦`；收到 `seat.invitation.rejected from 小明`；页面提示“小明 拒绝了上麦邀请” | 显示“房主邀请你上麦 / SEAT 02”卡片；收到 `seat.invited 2号麦 from 小周`；拒绝 API 第二行为 `to 小周 seat.invitation.rejected`，卡片关闭 | `Host 邀请 2 号麦后 Audience 拒绝，邀请卡关闭且 Host 收到反馈` |
| VR-E2E-06 | 双方在线，2 号麦为空 | 选择 2 号麦，邀请小明上麦 | 接受邀请；成功后再次主动下麦 | 收到 `seat.invitation.accepted 2号麦 from 小明` 后写 `seats=2号麦 小明`；收到 `seat.left` 后写 `seats=2号麦 空` | 接受 API 首行为 `rtm.publish USER`，第二行为 `to 小周 seat.invitation.accepted 2号麦`；Storage 事件驱动 2 号麦显示自己；下麦后恢复空麦 | `Host 邀请获接受后占用 2 号麦，Audience 可再次下麦` |
| VR-E2E-07 | Audience 已经占用 2 号麦 | 选中小明；依次静音、解除静音、下麦 | 观察自己的麦位和输入条状态 | API 依次包含 `forcedMutedUserIds=小明`、`forcedMutedUserIds=空`、`seats=2号麦 空`；选中卡从“静音”切换为“解除静音”，最终 2 号麦为空 | 强制静音后底部显示“已被静音”，解除后恢复“闭麦”，强制下麦后恢复“申请上麦”；每次 Storage `UPDATE` 都展示四项全量 Metadata | `Host 可对在麦 Audience 强制静音、解除静音并强制下麦` |
| VR-E2E-08 | 双方在线，Host URL 已带本轮身份 | 点击“暂时离开”；在入口点击“以 Host 身份返回” | 留在房间观察 Host 状态 | 暂离执行 `rtm.unsubscribe voice-room-...-xxxx`，入口保留返回按钮；返回后 `pageUid`、`roomId`、nickname 不变，重新执行 `presence.setState` 和 `rtm.subscribe` | 收到 Host `REMOTE_LEAVE` 后 1 号麦昵称降级为 `Host`、状态为 `AWAY`，上麦申请禁用；收到 Host `REMOTE_JOIN 小周 (uid缩写)` 后清除 AWAY 并恢复“小周” | `Host 暂时离开后 Audience 显示 Host 和 AWAY，原 Host 可返回同一房间` |

## 组合回归原则

1. 每条用例创建独立房名，避免目录记录跨用例污染。
2. 先等待双方完成实际房间订阅和首个 Storage 快照，再操作依赖权威 Metadata 的按钮。
3. 对瞬时动作同时检查发送端 API 和接收端 Event；对权威状态同时检查 Host 写 API、双方 Storage Event 和最终 UI。
4. Storage `SNAPSHOT` / `UPDATE` 的 Event 摘要检查四项全量 Metadata，不把 `initialize` 当 Event 内容，也不按 diff 断言。
5. USER／MESSAGE publish 的类型检查首行 tag；第二行 USER 检查目标 nickname、消息 type 和麦位，MESSAGE 检查频道短标识、`to ALL` 和消息 type。
6. Presence 加入/离开检查 nickname 与缩写 UID；不生成或断言 `INTERVAL`。
7. 流程失败时优先读取 Playwright trace，区分是按钮不可操作、发送 API 缺失、接收 Event 缺失，还是 Event 已到但业务 UI 未消费。
